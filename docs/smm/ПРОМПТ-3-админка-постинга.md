# ПРОМПТ-3 · Управление постингом из `/admin/content`

Скопировать целиком в агента, работающего в репозитории `skyline-digital`.

---

Ты дорабатываешь **студию контента** в проекте `skyline-digital` (Next.js 15 App Router,
TypeScript, Tailwind, Supabase, деплой на Vercel). Цель: из `/admin/content` один человек
управляет всем месяцем постинга — импорт плана, рендер, аппрув, расписание, публикация,
метрики. Ничего не публикуется в соцсети без явного нажатия человеком кнопки «Одобрить».

## 1. Семь задач по приоритету

### 1.1 Крона нет вообще — сделать первым

В корне репозитория **нет `vercel.json`**, поэтому `/api/cron/content` никогда не
вызывается: вся автопубликация сейчас мертва. Создай:

    {
      "crons": [{ "path": "/api/cron/content", "schedule": "*/15 * * * *" }]
    }

Vercel Cron работает **в UTC**. Ташкент = UTC+5, значит пост на 10:00 по Ташкенту —
это 05:00 UTC. Запуск раз в 15 минут + сравнение `scheduled_at <= now()` снимает вопрос
часового пояса: время хранится в `timestamptz`, админка показывает и принимает его
в `Asia/Tashkent`. Заведи `src/lib/content/tz.ts` с парой `toTashkent` / `fromTashkent`
и используй её везде в UI — сейчас в `page.tsx` дата режется через `slice(0,16)`,
это показывает UTC и будет врать на 5 часов.

Добавь `CRON_SECRET` в `.env.example` и в переменные Vercel.

### 1.2 `TELEGRAM_CHANNEL_ID` не задан

`publish-telegram.ts` читает `TELEGRAM_CHANNEL_ID`, а в `.env.local` есть только
`TELEGRAM_CHAT_ID` (чат лидов). Канал и чат лидов — разные вещи, смешивать нельзя.
Добавь переменную, а в админке — блок «Диагностика» вверху `/admin/content`, который
показывает по каждой площадке: настроена / не настроена и чего именно не хватает.
Молчаливый отказ публикации недопустим.

### 1.3 Импорт готового плана

Источник правды на сентябрь — `docs/smm/content-plan-2026-09.json`: 16 постов, поля
`id, date, time_instagram, time_telegram, rubric, title, format, slides[],
caption_instagram, caption_telegram, platforms, status`.

Сделай `scripts/content/import-plan.mjs` + кнопку «Импорт плана» в админке:

- маппинг `slides[]` плана → `postSpecSchema`; если тип слайда не проходит zod —
  импорт этого поста падает с внятной ошибкой, а не молча пропускает слайд;
- `slug` = `id` из плана, импорт **идемпотентный** (upsert по `slug`, повторный
  запуск не плодит дубли и не затирает уже одобренные посты);
- `scheduled_at` собирается из `date` + `time_instagram` в зоне Ташкента;
- `status` плана → статус в БД: `ready` → `review`, `draft` → `draft`,
  `blocked` → `blocked`. **Никогда не `approved`**: аппрув ставит только человек.
- отчёт после импорта: сколько создано, обновлено, пропущено, с ошибками.

### 1.4 Instagram — вторая площадка

Новый `src/lib/content/publish-instagram.ts` по Instagram Content Publishing API.
Проверенные ограничения (сентябрь 2026):

- нужен Instagram **Business**-аккаунт, связанный с Facebook Page; права
  `instagram_business_content_publish` (и `instagram_business_basic`);
- два шага: `POST /<IG_ID>/media` создаёт контейнер → `POST /<IG_ID>/media_publish`
  публикует по `creation_id`;
- карусель: контейнер на каждую картинку с `is_carousel_item=true`, затем родительский
  с `media_type=CAROUSEL` и `children`. **Максимум 10 элементов** — у нас есть пост
  на 8 слайдов (30.09), в лимит проходит, но валидацию поставь;
- **картинки только JPEG.** Наш рендер отдаёт PNG — либо `render.ts` учится писать
  `.jpg` (качество 92), либо конвертация на лету перед загрузкой. Это самая частая
  причина ошибки «media upload failed», проверь первым делом;
- медиа должно лежать на **публично доступном** URL на момент публикации. Подписанные
  URL из Supabase Storage подходят, но TTL ставь не меньше 30 минут: Meta забирает файл
  асинхронно;
- сторис: `media_type=STORIES`, одна картинка, без карусели;
- лимит **100 публикаций за скользящие 24 часа**, карусель считается за одну.

Ошибки Meta пиши в `content_publications.error` целиком (код + сообщение), в UI —
кнопка «Повторить». Повтор не должен создавать дубль публикации: уникальный индекс
`(post_id, platform) where status = 'published'` уже есть, опирайся на него.

### 1.5 Очередь напоминаний для того, что не автопостится

LinkedIn с личного профиля через API требует продукта «Share on LinkedIn»
(`w_member_social`) и отдельного приложения — для студии из одного человека это
несоразмерная возня. Facebook Page — тоже отдельный токен страницы.

Поэтому: статус `manual` в `content_publications`. Крон, дойдя до времени поста
с площадкой без настроенного API, не публикует, а шлёт в Telegram-чат лидов
(`TELEGRAM_CHAT_ID`) напоминание: заголовок, площадка, время, прямая ссылка
`/admin/content/<id>`, ссылки на скачивание готовых картинок и текст подписи одним
блоком для копирования. Человек публикует руками и жмёт «Опубликовано вручную».

### 1.6 QA-гейт перед аппрувом

В `docs/smm/QA.md` 27 пунктов. Часть проверяется кодом — перенеси их в `guard.ts`
как `level: "error"` (блокируют переход `review → approved`) и `"warning"`:

- ошибка: пустая подпись для площадки из `platforms`; нет вопроса читателю
  (подпись не содержит `?`); нет CTA на комментарий с ключевым словом; хэштеги
  непусты (правило студии — ноль хэштегов); число слайдов вне 1–10;
  цена в тексте, не совпадающая с прайсом из `docs/smm/brain.md`;
- предупреждение: подпись Telegram длиннее 1024 символов (уйдёт отдельным
  сообщением); последний слайд не типа `cta`; нет альтернативного текста.

Кнопка «Одобрить» дизейблится, пока есть хоть одна `error`, и рядом список причин.
Сейчас `approveAction` меняет статус без единой проверки — это дыра.

### 1.7 Метрики и недельный отчёт

`GET /<IG_MEDIA_ID>/insights` после публикации (первый сбор через 24 часа, второй через
7 дней) → `content_metrics`. Новая вкладка `/admin/content/metrics`: таблица постов
с охватом, сохранениями, пересылками, комментариями и медианой по рубрике, чтобы было
видно, какая рубрика умирает. Правило из `QA.md`: формат, три поста подряд ниже медианы,
подсвечивается красным.

## 3. Запреты

- Не публиковать ничего из статуса ниже `approved`, ни из крона, ни из UI.
- Не хранить токены в коде и в БД — только переменные окружения.
- Не выкладывать `SUPABASE_SERVICE_ROLE_KEY` в клиентский бандл: все действия —
  серверные экшены, `getSupabaseAdmin()` только на сервере.
- Не менять существующую схему БД миграцией, которая ломает данные: только
  `alter table ... add column if not exists` новой миграцией `0012_`.
- Не удалять и не переписывать `publish-telegram.ts`, он рабочий.
- Не придумывать цены и цифры: единственный источник — `docs/smm/brain.md`
  и калькулятор `src/lib/pricing/`.

## 4. Критерий приёмки

Один сценарий целиком: импортировал план → открыл пост 11.09 → увидел превью
5 слайдов → нажал «Рендер» → картинки в Storage → гейт зелёный → «Одобрить» →
поставил 11.09 10:00 → дождался крона → пост вышел в Telegram и в Instagram
каруселью, `content_publications` содержит две строки со ссылками, а в чат лидов
пришло напоминание про LinkedIn на 17:00.
