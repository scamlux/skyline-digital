# Architecture Decision Records

Короткие записи неочевидных технических решений (§10.6 ТЗ): контекст · варианты · выбор · последствия.

Статусы: **accepted** — решение принято и действует · **open** — отклонение зафиксировано, но требует решения владельца (пока считается дефектом кода относительно ТЗ).

| ADR | Тема | Статус |
|---|---|---|
| [0001](0001-pdf-engine-puppeteer.md) | PDF-движок: Puppeteer вместо @react-pdf/renderer | accepted (§9 явно приглашал ADR) |
| [0002](0002-stack-deviations.md) | Отклонения стека от §2 (AI-провайдер, 3D, npm, Next 16, static-проекты) | **open** — нужен сайн-офф владельца |

> Эти ADR созданы задним числом в ходе аудита (`docs/AUDIT.md`), чтобы зафиксировать уже принятые/накопившиеся решения. `open`-отклонения НЕ узаконивают нарушение ТЗ — они лишь делают его явным для решения.
