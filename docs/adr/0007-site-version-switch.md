# ADR 0007 · Переключатель версий сайта (old / Studio / Референс)

Дата: 2026-10-23 · Статус: принято (фаза 0) · Связано: `docs/plan-site-versions.md`, `docs/TZ-site-versions.md`

> План и ТЗ называют этот документ `0013-site-version-switch.md`; в репозитории
> ADR пронумерованы по порядку, а 0005–0006 уже зарезервированы планом редизайна (`docs/REDESIGN-PLAN.md`), поэтому — 0007.

## Контекст
Нужно держать в проде текущий («старый») дизайн и по кнопке из админки переключать весь
публичный сайт на один из двух новых вариантов. Варианты раскатываются постранично, и
на каждом этапе сайт должен быть цельным: без страниц, где новый каркас обёрнут вокруг
старого тела или наоборот.

## Решение
1. **Настройки.** `settings.site_version ∈ old|studio|ref` и `settings.brand_accent ∈
   dark-blue|burgundy|khaki|dark-green|brass` (миграция `0014_site_version.sql`,
   идемпотентная). Пресеты акцента — точные значения `THEMES` из эталона. Номер 0014,
   а не 0013 из плана: `0013_pipeline.sql` уже был в master (потом откачен), и запись
   версии 0013 в истории миграций Supabase могла бы заставить пропустить новый файл.
2. **Каркас в странице, а не в layout.** `Loader/Header/Footer` переехали из
   `[locale]/layout.tsx` в `SiteShell`. Layout оставил только `<html>/<body>`, JSON-LD,
   провайдер переводов и аналитику. Причина: вариант выбирается на уровне страницы
   (страница без готового варианта целиком уходит в `old` вместе с каркасом), а layout
   не знает, какая страница под ним.
3. **Диспетчеры.** Главная — диспетчер (`HOME_VARIANTS` + `resolveVariant`); тело
   главной перенесено в `components/home/variants/OldHome.tsx` через `git mv` без
   правок (переименован только экспорт). Остальные страницы и `not-found` пока
   обёрнуты в `withOldShell` — правка в 3 строки на файл, тела не тронуты.
4. **Чтение настроек.** `getActiveVersion()/getBrandAccent()` (`src/lib/site/active.ts`)
   при ошибке БД **бросают**, а не возвращают фолбэк. Иначе сбой Supabase во время
   перегенерации запёк бы `old` в кэш и молча переключил прод. Фолбэк `old` — только
   если Supabase не настроен или строки нет (миграция не применена).
5. **Кэш.** Без `unstable_cache`/`revalidateTag`: при сохранении `site_version` или
   `brand_accent` вызывается `revalidatePath("/", "layout")` (по документации Next 16.3 —
   «revalidating all data»). Страницы остаются SSG (`●`), ISR не теряем.
6. **Валидация на сервере.** `saveSetting` отклоняет недопустимые значения этих двух
   ключей — сырой key-value редактор тоже пишет через него.
7. **Локаль в обёртке.** `withOldShell` сам вызывает `setRequestLocale` до рендера
   каркаса. Без этого `Header/Footer` читали локаль динамически и 9 страниц теряли SSG.

## Проверка фазы 0
- Таблица роутов `next build` до/после **идентична** (все страницы `●`).
- Видимый текст 10 страниц (ru/en, главная, услуги, проекты, детальные, about, contact,
  calculator, audit) идентичен; DOM отличается только позицией пустой границы Suspense
  `<!--$--><!--/$-->` (ничего не рендерит). 404 — идентичен полностью.
- 404 из `notFound()` внутри страниц (`/projects/<нет>`, `/services/<нет>`) и битый токен
  сметы ведут себя как в проде (тот же статус, тот же набор шапки/подвала).
- Мобильные скриншоты — настоящий рендер 390 (puppeteer, `isMobile`, без горизонтального
  скролла): `/about` совпадает с продом байт-в-байт, главная — визуально (отличаются только
  анимированные звёзды фона).

## Дополнение (фаза 1, шаг 1) — как новые варианты подключают стили и шрифт

**Проблема.** Импорт `.css` (и `next/font`) из компонента каркаса Turbopack добавляет в CSS
**всех** маршрутов, до которых модуль достижим по графу импортов — в том числе через
`import()` и `next/dynamic` (проверено: обе попытки оставляли лишний stylesheet 29,5 КБ
с Onest на страницах старого дизайна).

**Решение.** Стили варианта лежат в `public/variants/ref.css`, шрифт Onest — self-hosted в
`public/fonts/onest/` (OFL, `unicode-range` как у Google: латиница с ʻ U+02BB, кириллица).
`RefChrome` рендерит `<link rel="stylesheet" precedence="default">` — React 19 поднимает его
в `<head>` и ждёт загрузки только на страницах, где каркас отрисован; шрифт
предзагружается через `preload()` из `react-dom`. Публичные файлы отдаются с
`max-age=0, must-revalidate`, версия в URL не нужна.

**Проверено:** на старых страницах число stylesheet (1) и font-preload (6) совпадает с
эталоном, `onest`/`/variants/` в HTML нет; на Референсе ссылка в `<head>`,
`document.fonts.check` для Onest — true, переход Референс → старая страница → назад без ошибок.

**Превью без БД.** `SITE_VERSION_OVERRIDE` / `BRAND_ACCENT_OVERRIDE` читаются в
`getActiveVersion()/getBrandAccent()` при локальной сборке; при `VERCEL_ENV=production`
игнорируются. Нужны, потому что локальная сборка смотрит в прод-БД.

## Последствия и долги
- `not-found` получает каркас через обёртку; у него нет `params`, локаль берётся из
  middleware. `error.tsx` в проекте нет.
- Ворота в ТЗ записаны как `pnpm …`, а проект на npm: используем
  `npx tsc --noEmit && npm run lint && npm run build && npm test`.
- Миграцию `0013` применить через SQL-editor Supabase. До этого сайт работает как
  сейчас (нет строки → `old`), но переключатель в админке создаст строку сам.
- Фаза 1: каркасы Studio/Референс, Onest на обёртке варианта, CSS акцента только под
  `[data-site]`.
