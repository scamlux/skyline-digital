# ТЗ для Claude Code · Варианты сайта Studio + Референс с переключателем из админки

> **Как пользоваться:** вставь это сообщение (или «выполни `docs/TZ-site-versions.md`»)
> в Claude Code CLI/агенте в корне репозитория `skyline-digital`. Это постановка задачи;
> архитектура подробно — в `docs/plan-site-versions.md`; **пиксельный эталон** —
> `docs/reference/artifact-skyline.html` (открой в браузере, переключай версии и акцент).

---

## Роль и задача
Ты — ведущий разработчик Skyline Digital. Перенеси из эталона два **новых** варианта сайта
(**Studio** и **Референс**) в реальный проект и дай переключать активный вариант и акцент
бренда из админки. Работай автономно по правилам `CLAUDE.md`; останавливайся только по
поводам из его раздела «Когда останавливаться».

## Жёсткие правила (не нарушать)
1. **Старый дизайн не трогаем.** Текущий код главной и страниц переезжает в `Old<Page>.tsx`
   вырезать-вставить, 1:1, без правок визуала/токенов. Вариант `old` = то, что на проде сейчас.
   В эталоне `#ver-old` — для сравнения, его в код НЕ портируем.
2. **Делаем только Studio и Референс.** Верстаем компонентами (RSC + ленивые клиентские
   острова `dynamic(..,{ssr:false})`), на реальных данных (`getProjects()`), i18n (next-intl,
   ru/en/uz), 3D (R3F/drei). Не копируем один HTML целиком — раскладываем на компоненты.
3. **Переключатель — только из админки.** Публичного тумблера на боевом нет. Активный
   вариант = настройка `site_version`, акцент = `brand_accent` (таблица `settings`).
4. **Перенос эффектов — пиксельно по эталону.** Для сигнатурных вещей бери **точные**
   значения из `docs/reference/artifact-skyline.html` (цвета-переменные, `cubic-bezier`,
   длительности, радиусы, clip-path, логику JS), а не пересобирай «по описанию».
5. **Акцент бренда = основной цвет.** `brand_accent` через `--acc`/`--acc-ink` (+ производные
   `color-mix`) перекрашивает **почти всё цветное** в обоих вариантах: кнопки, ссылки,
   акцентный текст, свечения/градиенты, 3D-подсветку, курсор, `::selection`, индикаторы,
   hover/active/focus. Нейтральные фон/текст/линии — из токенов варианта. Старого не касается.
6. **Ворота перед каждым коммитом:** `pnpm typecheck && pnpm lint && pnpm build && pnpm test`
   зелёные. Для готового экрана — скриншот Playwright 1440px и 390px в `screenshots/`,
   сам посмотри и сверь с эталоном. Неочевидные развилки — ADR в `docs/adr/`.
   Никаких хардкод-цветов/отступов в JSX — только токены/переменные.

## Архитектура (кратко; детали в плане)
- Каждая публичная страница — тонкий диспетчер: читает `site_version`
  (`getSetting<SiteVersion>("site_version","old")` из `src/lib/portfolio.ts`) и рендерит
  `Old<Page> | Studio<Page> | Ref<Page>`; нет варианта у страницы → фолбэк на `old` целиком.
- Каркас (`[locale]/layout.tsx`) тоже вариантный: ставит `data-site`, подключает Onest +
  акцент и вариантные Header/Footer/курсор/preloader. Для `old` — текущий каркас без изменений.
- Изоляция стилей: переменные и CSS новых вариантов — только под `[data-site="studio"]` /
  `[data-site="ref"]`, чтобы не течь в старый дизайн. Onest — через next/font, навешивать
  на обёртку варианта, а не на `<html>`.
- Кэш: при смене `site_version`/`brand_accent` ревалидировать (`revalidateTag("site-settings")`
  + `unstable_cache` в `getSetting`); фолбэк — `force-dynamic` на диспетчерах. Решение — в ADR.

## Данные (миграция `supabase/migrations/0013_site_version.sql`)
```sql
insert into public.settings (key, value) values
  ('site_version', '"old"'::jsonb),
  ('brand_accent', '"dark-blue"'::jsonb)
on conflict (key) do nothing;
```
`site_version ∈ old|studio|ref`, `brand_accent ∈ dark-blue|burgundy|khaki|dark-green|brass`.

## Админка
- `src/app/admin/settings/SiteVersionSwitcher.tsx` — сегменты **Старый/Studio/Референс** →
  `saveSetting("site_version", …)` (экшен уже есть в `src/app/admin/projects/actions.ts`).
- Рядом — **Акцент бренда**: 5 образцов → `saveSetting("brand_accent", …)`.
- Оба сверху `src/app/admin/settings/page.tsx` (сырой key-value редактор оставить).
  Существующий гейт авторизации админки не ослаблять.

## Что переносим из эталона (сверяйся с файлом)
**Studio** (`#ver-studio` / классы без префикса): параллакс-hero + восход, крупный Onest,
анимированные услуги (из `SERVICE_KEYS` + i18n + `basePriceUsd`), горизонтальная карусель
проектов (из `getProjects()`), scroll-progress «Процесс», стек/о себе/CTA — реальные ссылки.

**Референс** (`#ver-ref` / `.r-*`): preloader со счётчиком % и «Пропустить»; кастомный курсор
`#rcursor` (десктоп, только в ref); кинетик-hero с ротатором слов (не сдвигает соседей);
полноэкранное меню-модалка; индекс проектов со строками и плавающим hover-превью `.r-preview`;
depth-«Философия» на `position:sticky` (scale/blur/radius→0); **FLIP-открытие кейса из кликнутой
строки** (`openCase()` — медиа «вырастает» из `getBoundingClientRect()` строки в фуллскрин,
`transform-origin:0 0`, обратное закрытие, фолбэк reduced-motion); «Что мы делаем» — pinned
horizontal scroll. Кейсы наполнять из `getProjects()`, ссылки «Открыть сайт» — `project.url`.

⚠️ На обёртке Референса **не ставить `overflow:hidden`** (ломает sticky-depth — проверено).

## Порядок (пострановая раскатка на весь сайт)
0. **Каркас+инфраструктура:** `SiteVersion`+`getActiveVersion()`, вариантный каркас, паттерн-
   диспетчер, миграция `0013`, ревалидация, вынос главной в `OldHome`, переключатели в админке.
   Внешне сайт идентичен — проверить скриншотом. ADR `0013-site-version-switch.md`.
1. **Главная** — Studio + Референс (все эффекты выше).
2. `/projects` + `/projects/[slug]` → 3. `/services` + `/services/[slug]` →
   4. `/about` + `/contact` → 5. `/calculator` + `/estimate/[token]`.
6. Финал: прогон 3 версий × 5 акцентов по всем страницам, `docs/DESIGN-GAPS.md`, draft-PR.
Каждую фазу — отдельным PR (ветка на фазу), гейты зелёные, скриншоты 1440/390.

## Критерии приёмки
- Переключение версии и акцента из `/admin/settings` мгновенно отражается на публичном сайте.
- Акцент перекрашивает почти все цветные элементы обоих вариантов; старый дизайн не затронут.
- Сигнатурные эффекты Референса визуально совпадают с эталоном и плавны; `prefers-reduced-motion`
  уважается; мобилка 390px без горизонтального скролла и без ошибок консоли.
- Lighthouse ≥ 90 по всем метрикам, LCP ≤ 2.5 с (4G) на главной в Studio и в Референс.
- Все три локали заполнены; фактический контент без выдуманных кейсов/цифр.
- `pnpm typecheck && lint && build && test` зелёные.
